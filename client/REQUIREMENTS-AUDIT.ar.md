# Kanbot — تدقيق المتطلبات والتسليم

**النسخة:** v1.0 مع تحسينات إضافية  
**تاريخ التدقيق:** 6 نوفمبر 2026  
**نطاق العمل:** Frontend فقط — الخادم هو العقد المرجعي ولا يُعدَّل.

> هذا التقرير يميّز بين وجود التنفيذ في ملفات المصدر وبين نجاح الاختبارات الفعلية. لا أصف أي فحص لم يُشغَّل بأنه ناجح.

## 1. الخلاصة التنفيذية

تحتوي النسخة الحالية على تنفيذ مصدر لمعظم مجموعات القبول AUTH وPRJ وBL وSPR وAI، إضافة إلى ميزات اختيارية كثيرة. عالجت في هذه الجولة نقاطاً كانت أقل من مستوى التسليم: تقويم بسيط، وخطوط صغيرة/ضعيفة الوضوح، ونافذة إكمال السبرنت التي لم تعرض نقاط القصة ولم تكن مطابقة لاختيارات Backlog / Sprint الظاهرة في المرجع.

**الحكم الحالي:** تغطية المصدر واسعة، لكن لا يجوز اعتبار المشروع مختبَراً وجاهزاً نهائياً قبل تشغيل TypeScript وESLint وVitest وVite build والاتصال بالخادم على جهازك.

## 2. تدقيق المتطلبات الأساسية

الحالة في الجدول تعني أن السلوك موجود في المصدر بحسب مراجعة الملفات، وليس أنه اجتاز اختبار تشغيل شامل.

### المصادقة AUTH

| المعرّف | ما يجب أن يحدث | نتيجة مراجعة المصدر |
|---|---|---|
| AUTH-1 | تسجيل الاسم والبريد وكلمة المرور وتأكيدها، التحقق، أخطاء الخادم و409، منع الإرسال المكرر | موجود: `RegisterPage` و`AuthProvider` و`fieldErrors` |
| AUTH-2 | تسجيل الدخول، إظهار 401، ثم احترام `?redirect=` | موجود: `LoginPage` و`GuestRoute` و`safeRedirect` |
| AUTH-3 | حفظ JWT واستعادة المستخدم عبر `/auth/me` مع شاشة تحميل | موجود: `tokenStore` و`AuthProvider` |
| AUTH-4 | تسجيل الخروج ومسح الرمز والبيانات المخزنة في Query Cache | موجود: `AuthProvider.logout` و`queryClient.clear()` |
| AUTH-5 | حماية الصفحات الخاصة وتحويل المستخدم إلى تسجيل الدخول مع مسار العودة | موجود: `ProtectedRoute` |
| AUTH-6 | إنهاء الجلسة عند أي 401 غير تسجيل الدخول/التسجيل وإرجاع المستخدم إلى الصفحة المطلوبة | موجود: معالج 401 في `api/client.ts` و`AuthProvider` |

### المشاريع PRJ

| المعرّف | ما يجب أن يحدث | نتيجة مراجعة المصدر |
|---|---|---|
| PRJ-1 | قائمة المشاريع مع البيانات الأساسية والحالة الفارغة | موجود في `ProjectsPage` |
| PRJ-2 | إنشاء مشروع والتحقق من المفتاح و409 | موجود في `ProjectFormDialog` |
| PRJ-3 | تعديل الاسم والمفتاح والوصف مع توضيح أن مفاتيح المهام السابقة لا تتغير | موجود في نموذج التعديل ورسالة المساعدة |
| PRJ-4 | تأكيد حذف يسمّي المشروع ويحذر من حذف مهامه ودوراته | موجود في مسار حذف المشروع؛ راجعي نص التأكيد أثناء العرض |
| PRJ-5 | مبدّل مشاريع مع عنوان URL يحتوي معرف المشروع | موجود في `ProjectSwitcher` ومسارات `projects/:projectId` |

### Backlog والمهام BL

| المعرّف | ما يجب أن يحدث | نتيجة مراجعة المصدر |
|---|---|---|
| BL-1 | قائمة مرتبة وعدد المهام والنقاط وحالات الفراغ | موجود في `BacklogPage` |
| BL-2 | إنشاء سريع عبر Enter وإبقاء التركيز، وEscape للإلغاء | موجود في `QuickCreate` |
| BL-3 | تعديل جميع الحقول، أخطاء الخادم، والتأكيد عند إغلاق تغييرات غير محفوظة | موجود في `TodoDetailsDialog` |
| BL-4 | حذف المهمة مع تأكيد | موجود عبر نافذة التأكيد |
| BL-5 | إعادة ترتيب متفائلة مع rollback وخيار لوحة مفاتيح/نقل لأعلى أو أسفل | موجود عبر `dnd-kit` وقوائم الإجراءات؛ يعطّل السحب عند تفعيل الفلاتر مع توضيح السبب |
| BL-6 | بحث في المفتاح والعنوان والوصف والوسوم مع فلاتر النوع والأولوية | موجود؛ debounce مضبوط على 300ms |
| BL-7 | نقل المهمة إلى Backlog أو Sprint مخطط/نشط | موجود في إجراءات المهمة/تفاصيلها |

### Sprints واللوحة SPR

| المعرّف | ما يجب أن يحدث | نتيجة مراجعة المصدر |
|---|---|---|
| SPR-1 | إنشاء Sprint مخطط، وعرضه في Backlog مع مهامه وعددها ونقاطها | موجود |
| SPR-2 | تعديل/حذف Planned فقط وإرجاع مهامه إلى Backlog عند الحذف | موجود؛ الدورات النشطة والمكتملة لا تعرض إجراء الحذف |
| SPR-3 | بدء Sprint بتواريخ افتراضية والتحقق من نهاية التاريخ ومنع تفعيل أكثر من دورة | موجود |
| SPR-4 | لوحة بأعمدة To Do / In Progress / In Review / Done ومعلومات التقدم | موجود |
| SPR-5 | سحب البطاقات بين الأعمدة وإعادة ترتيبها مع بديل غير السحب | موجود عبر `dnd-kit` وأوامر البطاقة/تفاصيل المهمة |
| SPR-6 | إكمال Sprint مع عدد المكتمل وغير المكتمل، ونقاط القصة، ومكان ترحيل غير المكتمل، وملخص AI اختياري | حسّنت في هذه الجولة: عرض النقاط، ووجهات نقل على هيئة radio cards، والافتراضي Backlog، وخيار الملخص محدد افتراضياً ويمكن إلغاء تحديده |
| SPR-7 | سجل كل الدورات وتفاصيلها وإحصاءاتها وملخص AI المحفوظ وإعادة توليده | موجود في `SprintsPage` و`SprintDetailPage` و`SprintSummaryCard` |

### مساعد الذكاء الاصطناعي AI

| المعرّف | ما يجب أن يحدث | نتيجة مراجعة المصدر |
|---|---|---|
| AI-1 | Drawer في صفحات المشروع، محادثة كاملة، اختصارات، New chat، Markdown، thinking، وإعادة ضبط عند تغيير المشروع | موجود في `AssistantDrawer` و`AssistantContext` |
| AI-2 | توليد مسودات مهام قابلة للمراجعة والتحرير والاختيار ثم حفظ المحدد فقط | موجود في `GenerateTodosDialog` |
| AI-3 | تخطيط دورة حسب السعة والتركيز مع هدف قابل للتحرير ومجموع نقاط واختيار المهام | موجود في `PlanSprintDialog` |
| AI-4 | تلخيص الدورة النشطة/المكتملة، حفظ الخادم، عرض وقت التوليد وإعادة التوليد | موجود في `SprintSummaryCard` |
| AI-5 | Mock AI badge وحالات التحميل/الخطأ/إعادة المحاولة وعدم الحفظ التلقائي | موجود في `useAiStatus` ومكوّنات AI؛ حالة الوضع تُخزّن في Query مع `staleTime: Infinity` |

## 3. تدقيق المتطلبات غير الوظيفية NFR

| المعرّف | المتطلب | نتيجة التدقيق / ما يجب التحقق منه |
|---|---|---|
| NFR-1 | React 19 + TypeScript strict + Vite، لا `any` بلا تفسير، build وlint ناجحان | حدّثت الاعتماديات إلى React 19 وReact Types 19، و`strict: true` موجود. **يجب تشغيل typecheck/lint/build محلياً؛ لم أتمكن من إثبات نجاحها هنا.** |
| NFR-2 | حالات Loading / Empty / Error لكل عرض بيانات | توجد مكوّنات وحالات لهذه الشاشات. تحقق يدوياً من انقطاع الخادم، مشروع بلا مهام، وSprint بلا عناصر. |
| NFR-3 | تغذية راجعة لكل تعديل وتأكيد للإجراءات المدمرة | Toasts ورسائل Inline ونوافذ تأكيد موجودة. تحقق من كل Mutation أثناء العرض. |
| NFR-4 | قابلية الاستخدام من 1024px، والتابلت 768px، ولوحة أفقية عند الحاجة | توجد قواعد responsive. التقويم أعيد تصميمه ليستجيب للتابلت والهاتف؛ يلزم اختبار بصري على أحجام فعلية. |
| NFR-5 | HTML دلالي، labels، focus مرئي، dialog focus trap وEscape، بديل للسحب، AA | `Dialog` يطبّق حبس التركيز وEscape واستعادة التركيز. الأولوية والنوع لهما نص/أيقونة. يجب فحص تباين كل accent theme يدوياً. |
| NFR-6 | عدم وجود waterfalls غير لازمة، debounce ≥300ms، optimistic DnD | Query caching موجود، والبحث مضبوط على 300ms، ونقل المهام متفائل مع rollback. |
| NFR-7 | JWT فقط كبيانات مصادقة محلية، لا طباعة للرمز، Markdown بلا HTML خام | `tokenStore` لا يسجّل الرمز، و`react-markdown` لا يستخدم `rehype-raw`. تفضيلات الواجهة وبيانات الإضافات المحلية مخزنة محلياً وفق نطاق الإضافات. |
| NFR-8 | API layer منفصل، أنواع من عقد الخادم، بنية واضحة | البنية مقسمة إلى `api/`, `hooks/`, `context/`, `features/`, `types/`. لا تضع fetch داخل مكوّنات الصفحات. |
| NFR-9 | الإنجليزية فقط في الإصدار الأول | جعلت English هي اللغة الافتراضية دائماً، وأوقفت التحويل التلقائي حسب لغة المتصفح. احتفظت بمبدّل العربية كميزة إضافية طلبتِ الإبقاء عليها؛ استخدمي English أثناء اختبار القبول الرسمي. |

## 4. التعديلات المنفذة في هذه الجولة

### التقويم Calendar

- إعادة بناء صفحة الشهر بصرياً لتكون أوضح وأكثر هدوءاً.
- أضفت بطاقات ملخص: المهام المجدولة في الشهر، المفتوحة المتأخرة، المكتملة خلال الشهر، والمفتوحة بلا تاريخ.
- أضفت مرشحات All / Open / Done.
- أضفت دليل ألوان الأولوية.
- اختيار يوم يعرض قائمة ذلك اليوم كاملة في لوحة Agenda جانبية.
- بطاقة اليوم تفتح تفاصيل المهمة مباشرة.
- عند وجود أكثر من 3 مهام في يوم واحد، يظهر رابط يعرض بقية المهام في الـAgenda.
- تنسيق أسماء الأشهر والأيام يتبع اللغة المختارة.
- تحسين responsive للشاشات الأصغر؛ رُفعت أحجام عناصر النص الصغيرة على الهاتف لتبقى قابلة للقراءة.
- فصل منطق التقويم في `calendarModel.ts` وإضافة اختبارات لوظائف التصفية والتجميع والإحصاءات.

ملاحظة حسابية: عدّاد Scheduled مبني على `dueDate` داخل الشهر. عدّاد Completed مبني على `completedAt` داخل الشهر. عدّاد Overdue يستثني المهام المكتملة.

### الخطوط والوضوح

- استبدال عائلة النص اللاتيني إلى Inter مع أوزان متدرجة.
- استخدام IBM Plex Sans Arabic للنص العربي.
- توحيد الخط المستخدم للعناوين والنصوص لتقليل التباين غير المقصود بين العائلات.
- زيادة حجم النص الأساسي وبعض labels والنصوص الثانوية، ورفع line-height خصوصاً للعربية.
- الإبقاء على fallback system fonts إذا لم تتوفر خدمة Google Fonts.

### نافذة Complete Sprint

- تعرض عدد المهام المكتملة وغير المكتملة.
- تعرض `donePoints of totalPoints`.
- تعرض Backlog كخيار افتراضي.
- تعرض كل Planned Sprint آخر كخيار radio واضح عند توفره.
- تمنع الإكمال أثناء تحميل قائمة الدورات المخططة، وتوفر إعادة محاولة إذا تعذر تحميلها.
- خيار AI summary محدد افتراضياً كما في المرجع، ويمكن إلغاء تحديده.
- توضح أن الملخص سيُحفظ ضمن سجل الدورة.
- بعد الإكمال ينتقل المستخدم إلى صفحة تفاصيل الدورة.
- عولجت حالة تحميل الدورات المخططة بحيث لا تظهر رسالة «كل المهام مكتملة» عند وجود مهام غير منتهية ما زالت وجهة نقلها قيد التحميل.

### الخطوط والوضوح

- حدثت حزم React وReact DOM وTypeScript React types إلى إصدار 19؛ خطة التنفيذ تحدد React 19.
- الإنجليزية أصبحت الاختيار الافتراضي الصريح، والعربية لا تُفعّل تلقائياً حسب لغة المتصفح.
- أزلت ملف `.env` المحلي من الحزمة وأضفت `.env` وملفات البيئة المحلية إلى `.gitignore`، مع إبقاء `.env.example`.
- فحص مصدر مستقل: 122 ملف TS/TSX بلا أخطاء صياغة أو transpile، لا استيرادات نسبية مكسورة، 638 مفتاح ترجمة متطابق في كل لغة، و9 ملفات CSS متوازنة الأقواس. هذا ليس TypeScript typecheck ولا ESLint ولا Vite build.

## 5. الميزات الإضافية التي احتفظنا بها

| الميزة | طريقة العمل | حدودها |
|---|---|---|
| Overview | نظرة عامة على المشروع والتقدم والأولوية والمهام القريبة | تعتمد على بيانات API الموجودة |
| Today / Focus | مهام متأخرة/اليوم/القادمة مع روابط للتركيز | تعتمد على `dueDate` |
| Focus Mode | مؤقت تركيز واستراحة ومهمة واحدة | جلسات التركيز محلية وتعمل أثناء فتح التطبيق |
| Sprint Health | مقارنة المتبقي بالمسار المثالي | حساب مشتق من نقاط ومواعيد Sprint |
| Capacity | نقاط منجزة/متبقية/مرحّلة وسعة قابلة للتعديل | إعداد السعة محفوظ محلياً، وليس على الخادم |
| Burndown / Velocity | رسوم بيانية للدورة والسرعة التاريخية | مبنية على `completedAt` و`completedStats` المتاحة |
| Sprint Report | طباعة/حفظ PDF وتصدير CSV/Markdown | التقرير لا يضيف بيانات غير موجودة في الخادم |
| Templates | قوالب جاهزة ومخصصة للمهام | LocalStorage لكل متصفح |
| Browser reminders | تذكيرات بعد موافقة المستخدم | لا تعمل في الخلفية؛ يجب أن تكون صفحة Kanbot مفتوحة |
| Activity log | تسجيل تعديلات الجلسة الناجحة محلياً | آخر 200 حدث على هذا المتصفح فقط |
| Arabic + RTL | واجهة عربية اختيارية | خارج نطاق v1؛ English هي لغة التقييم الافتراضية |
| Theme + Accent | داكن/فاتح وخمسة ألوان تمييز | تفضيلات محلية |
| Command palette + shortcuts | Ctrl/Cmd+K واختصارات لوحة المفاتيح | إضافة واجهة فقط |
| Bulk actions + Undo | إجراءات جماعية وتراجع عن النقل | التراجع يرسل طلباً معاكساً للخادم ولا يضمن التراجع عن إجراء خارجي لاحق |
| AI helper additions | Stand-up وImprove/Estimate ومقترحات سياقية | كلها تمر عبر endpoints الموجودة، ولا تحفظ تلقائياً |

لم تتم إضافة أي ميزة من قائمة Out of scope مثل الفرق والمشاركة والمكلّفين والتعليقات وتغيير أعمدة سير العمل ومرفقات الملفات.

## 6. الأمان والبيئة

- `AI_API_KEY` يجب أن يبقى في `server/.env` فقط.
- `client/.env.example` يحتوي `VITE_API_URL=http://localhost:4000/api` فقط.
- لا تضعي مفتاح AI في `VITE_*`، لأن متغيرات Vite تُضمّن في ملفات المتصفح.
- ملف `.env` المحلي غير موجود في الحزمة النهائية ويُستثنى `.env.example` من `.gitignore`.
- لا ترفعي أي ملف بيئة حقيقي إلى GitHub.

## 7. فحوص يجب تنفيذها قبل التسليم

لم تكتمل عملية `npm install` في بيئة إعداد الحزمة بسبب انتهاء مهلة الاتصال بسجل npm. لذلك لم تُشغَّل الأوامر التالية بنجاح هنا ولا أضع لها علامة نجاح:

```bash
cd client
npm install
npm run typecheck
npm run lint
npm test
npm run build
```

بعد تشغيلها، احفظي النتائج الفعلية وأصلحي أي أخطاء تظهر. كذلك شغّلي Backend من `server/` ثم اختبري:

- `http://localhost:4000/api/health`
- `http://localhost:4000/api/ai/status`
- CORS عبر Vite على `http://localhost:5173`
- تسجيل/دخول/خروج/تحديث الصفحة/401 منتهية الصلاحية.
- دورة العمل كاملة من إنشاء المشروع إلى إنهاء Sprint وقراءة الملخص.
- التقويم على 1440px و1024px و768px و390px.
- الإنجليزية الافتراضية، ثم العربية يدوياً، ثم الوضع الداكن.
- `prefers-reduced-motion` ولوحة المفاتيح وfocus dialog.

## 8. خطوات العرض المقترحة

1. تسجيل حساب ثم إنشاء مشروع.
2. إضافة مهمة يدوياً إلى Backlog.
3. توليد مهام من AI، ثم تعديل المسودات وتحديد ما سيُحفظ.
4. تخطيط Sprint بالسعة والهدف ومراجعة المهام المقترحة.
5. بدء Sprint وتحريك البطاقات بين الأعمدة الأربعة.
6. فتح Complete Sprint وإظهار النقاط والخيارات والملخص.
7. عرض سجل Sprint وAI Summary.
8. عرض ميزات الإضافات: Today، Focus، Calendar، Capacity، Burndown، Velocity، Report، Templates، Activity.

## 9. ملاحظة حول التقييم

النسخة تغطي المتطلبات الوظيفية على مستوى المصدر بحسب المراجعة، وتحتفظ بإضافات يمكن أن تمنح نقاطاً إضافية. لكن التقييم النهائي يظل معتمداً على اجتياز أوامر البناء والاختبارات، وتشغيل الـBackend الحقيقي، وتجربة كل Acceptance Criteria أمام المراجع. لا تقدمي ادعاءً بأن build/lint/test ناجحة حتى تنفذيها محلياً.
