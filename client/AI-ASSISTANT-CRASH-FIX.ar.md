# إصلاح انهيار مساعد Kanbot (AssistantDrawer)

## ملخص المشكلة

ظهر في المتصفح:

```text
TypeError: Cannot read properties of undefined (reading 'length')
at AssistantDrawer (.../AssistantDrawer.tsx)
```

هذا خطأ في الواجهة أثناء عرض محادثة المساعد. لا يثبت وحده وجود مشكلة في Gemini؛ فهناك خطأ منفصل ظهر سابقاً من نوع `401 UNAUTHORIZED` يدل على جلسة غير صالحة أو طلب API من دون رمز الدخول.

## ما تم تعديله

1. **AssistantDrawer.tsx**
   - أضيفت قائمة محادثة احتياطية ثابتة إذا وصلت قيمة `messages` غير صحيحة أثناء تحديث الجلسة أو إعادة تحميل الوحدات.
   - استُخدمت القائمة الآمنة في `filter` و`length` و`map` حتى لا ينهار Drawer بسبب قيمة غير معرّفة.
   - حُميت نصوص رسائل المستخدم والمساعد من القيم غير النصية.
   - رُبط تأثير التمرير بقائمة الرسائل الآمنة.

2. **AssistantContext.tsx**
   - أضيف تحقق دفاعي من شكل قائمة الرسائل قبل تحويلها أو إرسالها.
   - جرى التحقق من أن استجابة المحادثة تتضمن `message.content` كنص غير فارغ. إذا اختلف شكل الاستجابة، تظهر رسالة خطأ قابلة للمعالجة بدلاً من إدخال قيمة غير صالحة في المحادثة.
   - أضيفت حماية إلى تحديثات قائمة الرسائل، كما يعيد `useAssistant` قائمة فارغة عند وصول قيمة سياق قديمة/غير متوافقة.

3. **Typewriter.tsx**
   - أضيفت حماية عند استلام نص غير صالح؛ يعرض المكوّن نصاً فارغاً بدلاً من قراءة `length` من `undefined`.

4. **useTyping.ts**
   - أضيف تحقق من قائمة العبارات قبل قراءة `length` أو التنقل بين العبارات.

5. احتُفظ بإصلاحات TypeScript وESLint السابقة في النسخة الكاملة، ولم تُعطّل قواعد lint.

## لماذا ظهرت أيضاً 401؟

- إذا فُتح رابط `http://localhost:4000/api/ai/status` مباشرة في شريط المتصفح، فلن يرسل المتصفح تلقائياً ترويسة `Authorization: Bearer ...` التي يضيفها تطبيق Kanbot، ولذلك قد تكون استجابة 401 متوقعة.
- عند الاختبار من داخل Kanbot، إذا أعاد طلب محمي 401 فهذا يعني أن رمز الدخول منتهي أو غير صالح. يجب تسجيل الخروج/الدخول مجدداً.
- لا يعالج هذا التعديل رمز JWT ولا يغير الخادم؛ فهو يمنع انهيار الواجهة عند الحالة غير المتوقعة فقط، مع إبقاء سلوك AUTH-6 (إنهاء الجلسة وإعادة التوجيه إلى تسجيل الدخول).

## طريقة التطبيق

1. فك ضغط `Kanbot-Frontend-AI-Drawer-Fix.zip`.
2. استبدل مجلد `client` الحالي بمجلد `client` الموجود داخل الحزمة. لا تستبدل `server`.
3. افتح Terminal داخل `client` وشغّل:

```powershell
npm run typecheck
npm run lint
npm test
npm run build
```

4. شغّل الخادم والواجهة، ثم سجّل الدخول من واجهة Kanbot نفسها.
5. افتح المساعد وأرسل رسالة قصيرة مثل `Hello Kanbot`.

## ما تم التحقق منه هنا

- فحص صياغة TypeScript/TSX للملفات الأربعة المعدلة نجح باستخدام TypeScript transpile.
- لم يتم تشغيل `npm run typecheck` الكامل أو `npm run lint` أو `npm test` أو `npm run build` في هذه البيئة؛ يلزم تشغيلها محلياً بعد فك الضغط.
- لم يتم اختبار الاتصال مع Gemini أو الخادم المحلي الحي من هذه البيئة.

## إذا استمر الخطأ

من أدوات المطور في المتصفح افتح Network، أرسل رسالة من داخل المساعد، ثم افحص طلب:

```text
POST /api/projects/:projectId/ai/chat
```

شارك `Status Code` و`Response` فقط بعد حذف أي ترويسة `Authorization` أو مفتاح API. لا تشارك JWT أو `AI_API_KEY`.
